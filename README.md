# entity-metamodel workspace

[![CI](https://github.com/VadimBabich/entity-metamodel-workspace/actions/workflows/ci.yml/badge.svg)](https://github.com/VadimBabich/entity-metamodel-workspace/actions/workflows/ci.yml)
[![OpenSSF Scorecard](https://api.scorecard.dev/projects/github.com/VadimBabich/entity-metamodel-workspace/badge)](https://scorecard.dev/viewer/?uri=github.com/VadimBabich/entity-metamodel-workspace)

The reference application for [entity-metamodel](https://github.com/VadimBabich/entity-metamodel),
typed queries for Spring Data R2DBC. It is a small document workspace (folders, files, versions,
tags, permissions) built the way an adopter would build it: Spring Boot 4.1, WebFlux, R2DBC,
PostgreSQL 18, an OpenAPI contract, Keycloak for identity.

It is a demonstration, not a product, and it is not published to any package registry.

**Status:** walking skeleton. Two endpoints list the top-level folders and a folder's children
through typed queries, showing a user only their company's folders that their grants allow; the
build, the tests, the local stack and CI are in place. The features follow.

Group memberships are read from Keycloak on a user's first request and again on a request once they are older
than 5 minutes (`workspace.mirror.membership-max-age`), so removing a user from a group takes effect within that
time. If Keycloak cannot be reached, the stored memberships stay in force and the reload is retried a minute later.
Known limitation: a user who sends no request is not refreshed until the periodic membership pass of a later step.

## Run it

Requirements: JDK 25, Docker.

```bash
./mvnw -B verify                                             # build, unit and integration tests
docker compose -f deploy/compose/compose.yaml up -d --wait   # PostgreSQL, Keycloak, S3
./mvnw -B clean package -DskipTests                          # exactly one application jar
java -jar workspace-app/target/workspace-app-*.jar           # the API on :8080, management on :9091
```

The whole stack, including the application container, Prometheus and Grafana, with an end-to-end
check that a Keycloak token reaches the API:

```bash
./mvnw -B clean package -DskipTests
deploy/compose/smoke-test.sh
```

| Service | Address | Development credentials |
|---|---|---|
| Application | http://localhost:8080 (the API); health, info and the Prometheus scrape on :9091, which the container does not publish | a bearer token from Keycloak |
| Keycloak | http://localhost:8180 (realm `workspace`) | admin `admin`/`admin`; eight demonstration users in two organizations, each with password = user name ([list](deploy/compose/README.md#keycloak)) |
| PostgreSQL | localhost:15432 | `workspace_app`/`workspace-app-local-development-password`; migrations `workspace_migrator`/`workspace-migrator-local-development-password` ([roles](deploy/compose/README.md#database-roles)) |
| S3 (Versity Gateway) | http://localhost:7070 | `workspace`/`workspace-secret-key` |
| Prometheus | http://localhost:9090 | — |
| Grafana | http://localhost:3000 | `admin`/`admin` |

Every credential above is a default for a disposable local stack.

## Layout

```
workspace-contract/   the OpenAPI document; server interfaces are generated from it
workspace-domain/     entities; their metamodels are generated by the entity-metamodel processor
workspace-app/        the Spring Boot application, Flyway migrations, tests
deploy/compose/       the local stack, its smoke test and a k6 load smoke
docs/                 documentation and code styles
```

## The library in this application

Each repository's queries live in a fragment that builds them with the generated metamodel:

```java
interface UserGroupRepository extends ReactiveCrudRepository<UserGroup, Long>, UserGroupQueries {
}

class UserGroupQueriesImpl implements UserGroupQueries {

  @Override
  public Mono<UserGroup> withKeycloakId(UUID keycloakId) {
    FluentSelect<UserGroup> group = FluentSelect.from(UserGroup__.ENTITY)
        .where(UserGroup__.KEYCLOAK_ID.is(keycloakId));

    return executor.one(group);
  }
}
```

`UserGroup__` is generated from the `UserGroup` entity at compile time; a renamed column is a compile
error, not a runtime surprise. Derived query methods and `@Query` strings are not used.
